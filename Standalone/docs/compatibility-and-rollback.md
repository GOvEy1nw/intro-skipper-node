# Compatibility and rollback

The current source target is Jellyfin `12.2.0`, following the integrated upstream `12.0` branch. This bridge cannot load on Jellyfin `12.1`; retain the earlier matching build there. The earlier S05 trial on Jellyfin `12.1` with Intro Skipper `12.0.5.8` completed authenticated scans and twelve accepted credits imports. Playback testing was waived by the user. The upstream integration has build and regression evidence and still requires paired installation and live acceptance on a compatible server.

Build the bridge with `dotnet build plugin/IntroSkipper/IntroSkipper.csproj -c Release`, preserving the normal dashboard build. Deploy both `IntroSkipper.dll` and `SegmentScanner.Contracts.dll` from `plugin/IntroSkipper/bin/Release/net10.0` using the server's normal plugin installation procedure. A standalone build deliberately omits the embedded dashboard and must not be used as the installed plugin. Existing plugin identity is retained; installing this fork replaces that plugin implementation and applies its remote-analysis database migration. Local development artifacts are unsigned and have not been installed.

Before a connected rollout, back up server plugin state with its SQLite journal/WAL, run offline with exports disabled, inspect a small reviewed set, then use a test server/library before any production subset. Keep one sidecar writer per destination.

IntroSkipper-Node uses protocol 3 and `/IntroSkipper/Remote/v3`. Install the matching EXE and both bridge DLLs. The plugin owns library/mode/path/resource/import policy in Nodes; hello reports only identity, hardware and executable recipes. New remote nodes start disabled. Existing declarations are adopted once into separate nullable policy/runtime columns; recurring hello never overwrites saved policy. Scope/profile or enablement changes invalidate old revisions without clearing accepted markers. The default local node remains enabled until changed. A v3 claim supersedes pre-policy snapshots and adoption schedules fresh targets. Finish outstanding reviews before upgrading, since current-input and policy checks still apply.

Connected work saves raw bundles under `state/results`. Explicit `review --apply` promotes only proposals whose payloads match a server-held receipt, after rechecking the current profile, inputs and revisions. Approval applies per analysis and leaves global automatic approval settings unchanged. An identical review retry is idempotent; a different review requires fresh work. See [the connected validation workflow](jellyfin-validation.md).

Stopping the worker leaves accepted segments and sidecars intact. Disable the node before returning its modes to local analysis and choose whether accepted detections are retained or reanalysed. Disabled-node leases cannot renew or publish; retain their proposals for inspection. Package downgrade can require restoring a compatible server database/configuration and worker-state backup. Uninstall intentionally preserves state and sidecars.

The user approved the labelled S05 calibration results and waived playback testing. Release still requires independent held-out evaluation, an approved model licence/provenance decision and live acceptance of each bridge change. Approval of these timings does not approve unattended detection across other media.
